# A01 · 加一个页面（面板侧）

> 本文只管**前端页面**。要加后端能力（action → CLI + HTTP）见主项目 README 的「新增功能域」。
> 两件事互不强制：一个页面可以完全不调 action（见 `pages/board/`）。

## 结论先看

**加一个页面 = 新建两个文件，不改任何全局文件。**

```
src/web/frontend/routes/<名>.ts        ← 必须有：路由声明（path / 导航 / 壳 / 组件位置）
src/web/frontend/pages/<名>/index.tsx  ← 必须有：页面组件（默认导出）
src/web/frontend/pages/<名>/api.ts     ← 建议有：本页对 action 的调用收口
src/web/frontend/pages/<名>/components/<组件名>/index.tsx  ← 可选：页面私有组件
```

路由 id 就是 `<名>`（routes 下的文件名）。路由由 `app/pages.ts` 里的
`import.meta.glob` 自动发现，不需要去任何注册表登记。

## 三步

### 1. 写路由声明 `routes/<名>.ts`

```ts
import { definePage } from './contract.js';

export default definePage({
  path: '/repos',                       // 必须以 / 开头；hash 路由里 # 之后的部分
  nav: { label: '仓库', order: 30 },     // 省略整个 nav 字段 = 这个页面不进导航
  layout: 'app',                         // 省略则 'app'；可选值见 app/layouts.ts
  page: () => import('../pages/repos/index.js'),   // 必须是函数，Vite 才保得住按页代码分割
});
```

几个字段的取舍：

| 想做的事 | 怎么写 |
| --- | --- |
| 出现在导航里 | 写 `nav: { label, order }` |
| 不进导航（详情页 / 向导步骤 / 全屏页） | **不写 `nav`**，配 `path: '/repos/:id'` |
| 换成左侧栏版式 | `layout: 'sidebar'`（或你新加的壳） |

### 2. 写页面组件 `pages/<名>/index.tsx`

```tsx
export default function ReposPage() {
  return <div className="stack" style={{ padding: 16 }}>…</div>;
}
```

- 需要路由参数：`const { id } = useParams<{ id: string }>()`
- 需要跳转：`<Link to="/repos/xxx">` 或 `useNavigate()`
- 筛选 / 分页 / 选中项**不要放 useState**，放 `useSearchParams()`——刷新、分享、后退都会用上
- 页面私有组件放本页 `components/<组件名>/index.tsx`；跨页面复用的才进全局
  `components/<名>/index.tsx`；可复用逻辑优先抽纯函数 / 纯模型（可单测）
- 样式优先用 `assets/base.css` 的原子类；颜色一律引用 `assets/tokens.css` 的变量，
  不写死色值；本页专属样式进 `assets/features.css`（用分段注释标明页面名）

### 3. 需要后端数据时写 `pages/<名>/api.ts`

```ts
import { useStore } from '../../store.js';

export function useReposApi() {
  const { client } = useStore();
  return {
    list: () => client['repo.list']({}),
  };
}
```

`client['<action id>']` 的参数与返回值类型由后端注册表推出，写错在编译期就红。
**页面里不要裸写 `fetch` / `api()`** —— 那会绕过类型契约（这条有 eslint 兜底）。

## 加一种新版式（左侧栏 / 分栏 / 全屏）

1. 新建 `app/shells/<x>-shell/index.tsx`，里面放 `<Outlet />`，内容用 `useNav()` 折出导航
2. `app/layouts.ts` 的 `LAYOUTS` 加一行 `<x>: <X>Shell`
3. 目标路由 `routes/<名>.ts` 写 `layout: '<x>'`

既有页面**一行都不用改**。`app/shells/sidebar-shell/` 就是照这个做的现成例子。

## 验证

```bash
pnpm typecheck                     # 类型
node --import tsx --test tests/unit/routes.test.mjs   # 路由声明：path 唯一、page 是函数、与 pages/ 一一对应
pnpm dev                           # 打开面板，看导航与深链
```

## 常见错误

| 现象 | 原因 |
| --- | --- |
| 页面不出现 | 没有 `routes/<名>.ts`（或文件名拼错），`import.meta.glob` 只认 `routes/*.ts` |
| 声明了路由但点进去白屏 | `pages/<名>/index.tsx` 不存在，或 `page` 不是函数（写成了 `import(...)` 的值） |
| 出现在顶栏壳里，但想要侧栏 | 路由声明里没写 `layout`，默认是 `app` |
| 加页面后 `pnpm typecheck` 红在深链 | 用了不存在的路由参数名；`useParams` 的键要和 `path` 里的 `:xxx` 完全一致 |
| 刷新 404 | 用了 BrowserRouter 风格的链接；这里必须用 hash 路由（静态服务没有 SPA fallback） |
