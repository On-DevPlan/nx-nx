## 2. P1 设计：三动作契约

### 2.1 动作面只有三个（+ 一个流水线入口）

| 动作 | CLI | HTTP | 语义 |
|---|---|---|---|
| 启动 | `nx-nx sg start <id>` | `POST /api/service-groups/:id/start` | 空间闸门 → 幂等启动 → 挂 watcher |
| 关闭 | `nx-nx sg stop <id> [--mode]` | `POST /api/service-groups/:id/stop` | 按 stopMode 执行，默认 auto 三重兜底 |
| 自愈开关 | `nx-nx sg autoheal <id> --on\|--off` | `POST /api/service-groups/:id/autoheal` | 翻转 `health.onDead` 并即时重建/停掉 watcher |
| （流水线） | `nx-nx sg run <id>` | `POST /api/service-groups/:id/run` | 已有，不属于「长脚本日常操作」 |

**自愈开关不新增配置字段**：单一事实源仍是 `health.onDead`（`restart` / `none`），
`autoheal` 是它的动作化投影。理由：两处布尔必然漂移；且 `onDead=none` 时
watcher 仍需运行（只记录不处理），「关自愈 ≠ 停监控」。

### 2.2 stop 默认选项（stopMode）

新增配置字段 `stopMode: 'auto' | 'script' | 'port' | 'pid'`，默认 `auto`（= 现有行为，向后兼容）。

| 模式 | 行为 | 适用 |
|---|---|---|
| `auto` | 关停脚本 → 杀端口 → 杀 pid（依次兜底） | 默认；不确定时用它 |
| `script` | 只跑组内 stop 脚本 | 服务自己有优雅退出协议 |
| `port` | 杀 `killPort ?? health.port` 的占用进程 | **用户点名的默认选项**：「直接关闭端口所在进程」 |
| `pid` | 只杀运行态记录的 pid | 端口被别人占用，不想误杀 |

`sg stop <id> --mode <m>` 可临时覆盖本次行为（不写回配置）；`sg set` 改的是持久值。

- 脚本三类角色按后缀分流：`*.mjs`（Node）/ `*.short.mjs`（沙箱）/ `*.shared.mjs`（只声明）。

  宿主只搭七座桥（`log / args / set / heap / panel / use / call`）；超时中断器 + 内存上限。
- 面板双桥：数据快照直接注入；**同步函数**经 `call()`（JSON 进出）；async 明确拒绝；
  内置别名（fs/网络/进程能力）不进沙箱。

  （`NX_HEAP_RESULT` 行，stdout 里摘除）。
- 跨 ns：`_runner.mjs` 先装载依赖面板（`NX_NS_IMPORTS`），面板里 `useSpace('名')`；
  `useSpace/listSpaces` 不算面板产出。
