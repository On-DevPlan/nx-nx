# nx-nx 模板功能与数据流向

> 生成日期：2026-11-10 · 基于 v0.10.0+（JS 版模板已下线，TS 版更名为 `server-cli-web`）
> 源码核对范围：`src/core/{templates,generate,template-hooks}.ts`、`src/modules/template/`、
> `src/runtime/{cli,api,server,registry,spec}.ts`、`src/modules/scaffold/`、`templates/*`
> 本文与源码一一对应；改契约前先核对上述文件。

---

## 1. 总览：定位与核心设计原则

nx-nx 是**通用的项目模板生成管理器**：`server-cli-web` 骨架只是第一个模板，
不是唯一模板。任何满足模板契约的目录都能被 `list / describe / preview / create`
四条路径一致地处理，不需要改 runtime。

支撑这个定位的三条结构性原则：

| 原则 | 落点 |
| --- | --- |
| **一处声明，两端生效** | 每条 action 同时声明 `cli` 路径与 `http` 路由，CLI 命令表、HTTP 路由表、help 文本全部由此派生——「面板上有按钮、CLI 里没命令」在结构上不可能发生（`runtime/registry.ts`） |
| **面板不认识任何具体字段** | 表单完全由模板的 option schema 驱动渲染；模板加一个选项，面板自动多一个控件，`view.tsx` 不写死任何模板字段（`modules/scaffold/`） |
| **静态声明 + 动态钩子收敛成一个接口** | 纯静态模板不被复杂化；值域依赖运行环境的选项（端口探测）与二进制产物（logo）走 `hooks.mjs`，通用生成器永远不认识「图片」这个概念（`core/template-hooks.ts`） |

## 2. 模板契约：`templates/<id>/`

```
templates/<id>/
├─ template.json   # 元数据 + 静态选项 schema（必需）
├─ hooks.mjs       # 动态选项 / 生成前后钩子（可选）
├─ README.md       # describe 面板展示（可选）
└─ files/          # 模板文件树（必需）；路径与内容里可用 {{var}} 占位
```

- **目录名即模板 id**；`template.json` 必须重复声明同一个 id（不一致 = 坏模板）
- `files/` 之外的文件不进生成结果；遍历时自动跳过
  `.git`、`node_modules`、`.DS_Store`、`template.json`、`*.log`、`*.tmp`
- 坏模板不吞掉也不中断：`listTemplates()` 收集成 `errors` 一并返回，
  面板能显示「哪个模板坏了、为什么」，而不是整个列表打不开

### 2.1 template.json

```json
{
  "id": "my-template",            // 必需，= 目录名
  "name": "人类可读名",            // 必需
  "description": "一句话",         // list / describe 展示
  "namePrefix": "nx-",            // 与 letters 选项配合派生 name
  "logo": true,                   // 默认 true；false = 模板没有 logo 概念，面板只展示项目名
  "outputMode": "siblings",       // 默认单工作区；siblings = 多兄弟工作区，必须 --dir
  "nextSteps": ["cd {{name}} && pnpm install"],
  "options": [ ... ]
}
```

**option 对象字段**：

| 字段 | 说明 |
| --- | --- |
| `name` | 选项名（即变量名），必需 |
| `type` | `string`（默认）/ `number` / `boolean` / `enum` / `letters` |
| `label` / `hint` | 表单标签 / 输入提示 |
| `required` | 必填；缺失时在变量解析阶段报错 |
| `default` | 默认值；未填且无默认时布尔落 false、其余落空串（留给钩子补） |
| `values` | type=enum 时的可选值数组（enum 缺 values = 坏模板） |
| `pattern` | 值格式约束（正则源码）；**声明了就必须被执行**——加载期校验正则合法性，解析期真正拦截 |

契约错误（非法 type、enum 缺 values、pattern 不是合法正则、选项缺 name）
都在**加载期**当场抛 `SPEC_ERROR`——拖到生成期才炸时用户已经填完一整张表了。

### 2.2 hooks.mjs

默认导出 `{ options?, beforeGenerate?, afterGenerate? }`，三者皆可选、可 async：

| 钩子 | 时机 | 用途 | 返回 |
| --- | --- | --- | --- |
| `options(ctx)` | 解析期 | 值域依赖运行环境的选项（探测空闲端口、列出撞色方案） | `OptionSpec[]`，按 name 合并进静态声明，同名以动态为准 |
| `beforeGenerate(vars, ctx)` | 生成前、目标检查**之前** | 补默认值 / 校验（如空端口补探测值、siblings 校验 --dir） | vars 补丁对象；抛错则整个生成中止 |
| `afterGenerate(targetDir, vars, ctx)` | 写盘之后 | 产出二进制产物（logo 六件套） | 任意值（`{note}` 会被展示） |

`ctx` 工具箱：`probePort(port)` / `probePorts({start, count})` / `cwd` / `dir`。
模板作者**不从 nx-nx 内部 import 任何模块**——需要的能力都由 ctx 给，
否则模板会与生成器内部路径耦合，生成器一重构所有模板都坏。

### 2.3 占位符 `{{var}}`

- 语法 `{{var}}`（`[\w-]+`），出现在文件**路径**（如 `bin/{{letters}}.mjs`）与**文本内容**两处
- GitHub Actions 的 `${{ ... }}` 天然不匹配（点号与空格不在字符类里），不会被误替换（有测试钉住）
- **两套渲染，刻意不对称**：
  - `renderString`（严格）：内容渲染用；引用未声明变量**抛错**——静默漏成字面量是坏产物
  - `renderMetaText`（宽松）：元数据展示文本用（description / nextSteps / hint / label）；未声明变量原样保留——`list` 阶段还没有 vars，抛错则整个列表打不开
- 文本 vs 二进制：扩展名白名单 + 内容无 NUL 字节才走替换；其余按字节原样复制。
  漏一个扩展名的后果不是报错，而是产物里留着字面 `{{var}}`（静默坏掉），
  所以白名单覆盖 `.go .mod .sum .sql .conf .example .dockerignore` 等非 JS 生态（mono-gf 踩过后补的）

### 2.4 派生变量（模板不用自己拼）

约定：名为 `letters` 的选项是项目字母（1~5 位小写字母，大小写宽容、自动 trim+lower）。

```
name      = namePrefix + letters        （prefix 可被 prefix 选项覆盖，显式空 = 无前缀）
title     = name
envPrefix = name 大写、连字符转下划线     （nx-ab → NX_AB）
```

派生出与模板 id 同名的项目会被拒。`resolveVars` 不认识具体模板——
它只认「名为 letters 的选项」这条家族约定。

## 3. 三个内置模板

| 模板 id | 形态 | 必填项 | 关键机制 |
| --- | --- | --- | --- |
| `server-cli-web` | 单工作区，nx- 前缀家族 | `letters` | 钩子探测端口（serve 7920 起、vite 再 +10）、afterGenerate 产出 logo 全套（svg+png+ico，每次现算杜绝「图与项目名对不上」的漂移） |
| `mono-gf` | 单工作区，必填 `name` | `name` | GoFrame + React + nginx + PostgreSQL 全栈；选项最多（12 个），pgPort 不探测——本机已有 PG 时应该连它 |
| `std-a-lang` | **siblings** 多兄弟工作区 | `lang`（可批量 `ts, go, py`） | `files/a_{{lang}}/` 的 `{{lang}}` 是**列表变量**：钩子 beforeGenerate 把逗号串拆成数组，引擎按笛卡尔积铺出 `a_ts/ a_go/ ...`，文本里各副本用对应标量值 |

`std-a-lang` 的 `outputMode: "siblings"` 语义：输出目录是 `a_<lang>/` 们的**父目录**，
必须 `--dir` 指定且必须为空；单 lang 与多 lang 走同一条分支，面板与 CLI 同一口径。
钩子不再需要 v0.6.x 的「母版-复制」workaround——展开是引擎原生能力
（`core/generate.ts` 的 `listVarExpansions`）。

## 4. 分层与职责

```
core/       零业务引擎                templates.ts（发现/加载/校验/resolveVars/渲染）
                                      generate.ts（遍历/展开/落盘）
                                      template-hooks.ts（钩子加载与执行）
modules/    功能域                    template/index.ts（action 声明）+ service.ts（业务真相）
                                      scaffold/（面板视图：view.tsx + option-form.ts + option-field.tsx + logo-preview.tsx）
runtime/    装配                      registry.ts（模块汇合 + 启动自检）
                                      cli.ts（argv → action）  api.ts（HTTP → action）
                                      spec.ts（flag 强转 + 路由编译 + 用法串）
web/        React 壳                  store.tsx（bootstrap + typed client） registry.ts（视图登记）
```

- 模块之间禁止互相依赖（eslint 强制；system 是刻意的聚合器例外）
- `modules/template/service.ts` 是模板域的**业务真相**：CLI 与 Web 面板共用这一层，
  action 只负责把两端不同的输入形态归一成同样的 ctx

## 5. 数据流向

### 5.1 全局图

```
                        ┌──────────────────────────────────────────────┐
                        │   templates/<id>/{template.json, hooks.mjs, files/}
                        └──────────────┬───────────────────────────────┘
                                       │ 读取 + 动态 import
        CLI (argv)                     ▼                      Web 面板 (React)
  ┌───────────────┐        ┌─────────────────────────┐        ┌───────────────────┐
  │ bin/nx-nx.mjs │        │  modules/template/      │        │ store.tsx         │
  │  → runtime/cli│──────▶│  index.ts  (action 声明)│◀──────│  typed-client     │
  │  解析/匹配/强转 │        │  service.ts (业务真相)   │        │  (action id → HTTP)│
  └───────────────┘        └──────────┬──────────────┘        └────────┬──────────┘
   argv → ctx                         │ 调 core                        │ fetch /api/*
        {transport:'cli'}             ▼                                ▼
                             ┌─────────────────────────┐        ┌───────────────────┐
                             │  core/templates.ts      │        │ runtime/server.ts │
                             │  core/template-hooks.ts │        │  静态面板 + /api/* │
                             │  core/generate.ts       │        │ runtime/api.ts    │
                             └──────────┬──────────────┘        │  路由表 ← action.http│
                                        │                        └───────────────────┘
                                        ▼
                              targetDir 落盘（{{var}} 渲染 / 二进制复制）
                                        │
                                        ▼
                              afterGenerate（logo 等模板专属产物）→ nextSteps 渲染
```

### 5.2 CLI 数据流（`runtime/cli.ts`）

```
argv
 │ splitGlobals          摘掉 --json / --store（全局 flag 可出现在任意位置）
 ▼
resolveCommand           声明路径与 argv 前缀逐 token 比较，最长匹配胜出
 │                       （逐 token 是必需的：'skill install --list' 的路径本身含 flag）
 ▼
parseRest                位置参数 + flag；布尔 flag 不吞下一个 token
 ▼
assertKnownFlags         未知 flag 报错（--fiile 这类拼写错误立刻被指出）；
 │                       例外：openFlags action 放行——模板选项由数据驱动，声明期无法枚举
 ▼
applySpec (spec.ts)      按 flag 声明强转类型/校验 enum/填默认值；位置参数映射成具名输入；
 │                       错误消息带完整「用法:」串（对外契约，agent 靠它分类失败）
 ▼
action.run(ctx, {transport:'cli'})          ← modules/template/index.ts
 │  template.create 的 run:
 │    1. service.describe(id)        拿钩子解析后的 option schema
 │    2. pickOptions(ctx, options)   按 schema 白名单挑键——ctx 里混着 CLI 全局 flag、
 │       平台 flag、action flag，不筛一遍用户任意输入会冲掉模板默认值
 │    3. parseSetList(ctx.set)       --set k=v 兜底（值带空格 / 选项名与 flag 撞名时用）
 │    4. service.create({id, options, dryRun})
 ▼
emit                     --json → JSON.stringify（机器可读）；否则 render(data) 人读文本
                         失败 → exit 1 + 可解析错误对象 {ok:false, error, code}
```

### 5.3 HTTP 数据流（`runtime/server.ts` + `api.ts`）

```
浏览器 fetch /api/templates/:id/create (POST {letters:'ab', dir:'...'})
 │
 ▼
server.ts     /api/* → handleApi；其余 → serveStatic（PUBLIC_DIR 越界校验）
 ▼
api.ts        ROUTES = ACTIONS.filter(http).map(compileRoute).sort(字面量段多者优先)
              （排序是必需的：GET /api/repos/status 与 GET /api/repos/:id 谁先声明谁赢，
               调整 actions 顺序会引发只在特定路径出现的运行时 bug）
 ▼
逐条尝试 route.regex.exec(pathname)
 ├─ 非 GET/HEAD 且 Origin 非本机 → 403（跨站防护：服务只绑 127.0.0.1，
 │   但用户浏览器里的任意页面都能向它发请求；浏览器跨域必带 Origin，curl 不带 → 放行）
 ├─ 命中：:param 解码进 raw；GET 用 querystring，其余读 JSON body（≤4MB）
 ▼
applySpec → action.run(ctx, {transport:'http'})     ← 与 CLI 同一个 run
 ▼
成功: sendJson(200, {ok:true, data})
失败: toErrorPayload → httpStatusOf(code) 映射 4xx/5xx（只在 core/errors 一处映射）
      INVALID_INPUT→400  NOT_FOUND→404  CONFLICT/BLOCKED→409  EXTERNAL→502  SPEC/INTERNAL→500
```

**错误契约**（全项目最重要的一条约定）：
失败（调用方无从处理）→ throw `NxError`；业务结果（UI 要弹窗让用户决策）→ `return {status}`。
历史上同一层并存 throw / {ok:false} / {status} / {available} 四种表达，上层只能靠字符串猜。

### 5.4 Web 面板数据流（`modules/scaffold/`）

```
启动
 │ store.tsx: GET /api/bootstrap（system.bootstrap）
 │   返回 {app, storePath, templatesDir, templates, templateErrors, commands}
 │   commands = 全量命令表（action id → cli/http 映射）——typed client 的路由来源，
 │   浏览器**不 import registry**（类型 import 编译期擦除，绝不会把 node 侧代码打进浏览器包）
 ▼
UI 初始化
 │ 左栏模板列表 ← boot.templates（坏模板列在 boot.templateErrors）
 │ 自动选中第一个 → client['template.describe']({id})
 │   返回钩子解析后的 options（端口默认值已探测）+ readme + nextSteps
 │   decorateMeta 宽松渲染：给 letters 就填 {{name}}，没给原样保留（预览时用户看得懂）
 │   用 default 预填表单——用户不改就能直接生成
 ▼
填写过程（三个实时反馈环）
 │ ① 按键可点性：blockingIssues(options, values) —— option-form.ts 是
 │    core/templates.ts resolveVars 的**前端镜像**，规则逐条对齐
 │    （tests/unit/option-form.test.mjs 拿真实模板库对拍，规则漂移直接红）。
 │    必填缺失 + 格式非法汇成一个 issues 数组 → 按钮禁用 + 底部提示同源展示。
 │    曾经面板写死 letters，mono-gf（name）与 std-a-lang（lang）按钮恒灰——教训。
 │ ② 目录可用性：check-dir 防抖 400ms → {exists, usable, entries}
 │ ③ logo 预览：LogoPreview 内联 SVG，改字母/配色立刻重绘（展示用色值副本；
 │    真实取值以模板钩子为准）。tpl.logo === false 的模板不画。
 ▼
预览 / 生成（走同一套白名单收集，与 CLI 的 collectOptions 同形）
 │ client['template.preview']({id, ...values, dir})   → 右侧文件树清单
 │ client['template.create']({id, ...values, dir})    → 确认弹窗 → 生成
 │   typed-client 运行时：从 boot.commands 找 http 路由 → :param 替换 →
 │   GET 拼 querystring / POST 发 JSON body —— action id 写错在编译期就红
 ▼
结果展示
 │ {count, outputDir, vars, files, extra.note, nextSteps}
 │ nextSteps 已用真实 vars 渲染（'cd nx-ab && pnpm install'）
 │ UI 选择（当前视图等）persist 到 localStorage；数据永远从 /api 拉，不持久化
```

### 5.5 生成流水线（`service.create` 的顺序有意为之）

```
loadTemplate(id)                     目录存在性 + template.json 加载期校验
   ▼
resolveOptions(meta, dir, ctx)       静态 options 打底 + hooks.options() 按 name 合并
   ▼                                 （面板 describe、CLI 白名单、create 三处同源）
resolveVars(meta, options)           ① 类型强转（boolean/number/enum/letters/pattern）
   ▼                                 ② 默认值填充 / 必填校验
                                     ③ 派生变量 name / title / envPrefix
   ▼
applyBeforeGenerate(dir, vars, ctx)  钩子补丁合并（补端口、std-a-lang 拆 lang 列表并强制 --dir）
   ▼                                 ← 必须在目标检查之前：钩子改的目录名要参与冲突检查
targetDir 计算                       --dir（绝对/相对 cwd）优先；否则 cwd/<vars.name>；
   ▼                                 siblings 模板无 --dir 时由钩子已在上面报错
   ▼
assertTargetUsable(targetDir)        存在且非空 → BLOCKED 拒绝，绝不静默覆盖
   ▼                                 （覆盖用户已有目录是不可逆事故，宁可在这一步烦人）
generate({templateDir, targetDir, vars, dryRun})
   │  walkTemplate(files/)           递归产相对路径清单（dry-run 与实际生成共用 →
   │                                 「预览看到的」与「实际写出的」必然一致）
   │  对每个 rel：
   │    listVarExpansions(rel, vars) 路径含数组变量 → 笛卡尔积展开多副本，
   │                                 副本内列表变量降为标量、其余同全局 vars
   │    路径安全检查（每个副本独立过）：
   │      · 渲染后每段不得是 '..' / '.' / 盘符 —— 即使 resolve 后仍在目标内也拒
   │        （'bin/../x' 规范化后是目标内的 'x'，逃逸检查抓不住它，但输入没洗干净就该报错）
   │      · resolve 成绝对路径后必须落在 targetDir 内（比对解析结果，不是字符串前缀）
   │    dryRun? 记账后 continue : mkdir -p + 写文件
   │      · isTextPath → 读 utf8 + renderString(严格) 写回
   │      · 其余 → copyFile 按字节原样复制
   ▼
applyAfterGenerate(dir, targetDir, vars, ctx)   模板专属二进制产物（logo 六件套）；
   ▼                                            放这里而不是 generate 内部，
   ▼                                            通用生成器永远不认识「图片」这个概念
nextSteps = meta.nextSteps.map(renderString)    用真实 vars 渲染
   ▼
返回 {status, template, outputDir, vars, files, count, dryRun, extra, nextSteps}
```

`preview` 与 `create` 共用 `resolveVars + applyBeforeGenerate + walkTemplate + listVarExpansions`，
只差 `dryRun`——不可能出现「preview 显示的和生成的不一致」这种错位。

## 6. 安全与健壮性设计清单

| 威胁 | 防线 | 位置 |
| --- | --- | --- |
| 模板 id 目录穿越 | id 必须单段、禁 `\ / ..` | `core/templates.ts loadTemplate` |
| 渲染后路径逃逸 | 非法段拒绝 + resolve 后必须落在 targetDir 内 | `core/generate.ts` |
| 覆盖已有项目 | 目标目录非空 → BLOCKED 拒绝 | `assertTargetUsable` |
| 项目与模板同名 | 派生 name === 模板 id → 拒绝 | `resolveVars` |
| 静态面板路径穿越 | resolve 后必须落在 PUBLIC_DIR 内 | `runtime/server.ts serveStatic` |
| 恶意网页跨站写 API | 非 GET/HEAD 校验 Origin 本机 | `runtime/api.ts originAllowed` |
| 用户输入冲掉模板默认值 | 按 schema 白名单 pickOptions | `modules/template/index.ts` |
| flag 拼写错误静默忽略 | 未知 flag 报错（openFlags 例外） | `runtime/cli.ts` |
| 请求体过大 | 4MB 上限 | `runtime/api.ts readBody` |

## 7. 一致性保证（测试钉住的契约）

| 不变量 | 钉子 |
| --- | --- |
| `${{ }}` 不被误替换（GitHub Actions） | `tests/unit/templates.test.mjs` |

## 8. 扩展路径：写一个新模板

1. `templates/<id>/` 下建 `template.json`（id 与目录名一致）+ `files/`
2. 需要环境相关默认值 → 加 `hooks.mjs`；需要二进制产物 → `afterGenerate`
3. 自检：`nx-nx template list`（无错误）→ `describe <id>` → `preview <id> --选项 值`
   → 真实生成一次并跑通构建/测试
4. 面板**零改动**：表单控件按 type 自动映射（boolean→checkbox、enum→select、
   number→number input、其余→text）；必填/选填徽标、阻塞提示、项目名推导全部由
   schema 推出

约束提醒（源自历史踩坑）：
- files/ 内引用的每个 `{{var}}` 都要能由 options + 派生 + 钩子提供（否则生成期抛「未声明的变量」）
- 值域随环境变的选项交给钩子，不要写死在 json（过期数据）
- siblings 模板必须声明 `outputMode: "siblings"`，且面板/CLI 会强制要求 `--dir`
